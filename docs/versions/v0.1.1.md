# 一、版本概述

## 1.1 版本目标

v0.1.1 不以增加大量新功能为目标。

本版本核心任务：

> 对 v0.1.0 基础版本进行工程化升级，使项目具备长期维护、持续扩展和多人协作开发能力。

---

# 二、为什么需要 v0.1.1


v0.1.0 已经完成：

- 页面框架
- 基础成长流程
- 本地数据保存


但是随着未来功能增加：

- 云同步
- AI Agent
- 完整课程体系
- 数据分析


原有结构可能出现：

- 页面代码过于复杂；
- 数据逻辑混乱；
- 内容和代码耦合；
- 数据迁移困难；
- 后续功能难以维护。


因此需要进行架构升级。

# 1. 项目目录架构重构


## 目标

建立清晰的职责边界。


调整为：


```text id="0bq4v1"
src/

├── app

├── pages

├── features

├── data

├── content

├── services

├── cloud

├── shared

├── hooks

├── types

└── utils
```


---

## 模块职责


### pages

负责：

页面组合。


例如：

```text id="0d3qkw"
Dashboard

Academy

Training

Journal
```


---

### features

负责：

业务能力。


例如：

```text id="2a8n5v"
learning

training

journal

assessment

growth
```


---

### shared

负责：

公共资源。


包括：

- UI组件
- 工具函数
- Hooks


---

# 2. 引入 Feature-Based Architecture


## 背景


之前：

页面驱动。


未来：

功能驱动。


---

## 调整前


```text id="b8a9se"
pages

↓

components

↓

logic
```


---

## 调整后


```text id="5k8jkp"
Feature

↓

Service

↓

Repository

↓

Database
```


---

## 收益


未来新增：

AI训练模块。


只需要：

新增：

```text id="z4u7rq"
features/ai-coach
```


不会影响其他模块。


---

# 3. 建立 Service Layer


## 目标

业务逻辑独立。


调整：

从：

```typescript id="g3m4n2"
Component

直接操作数据
```


变为：


```text id="d7e2qk"
Component

↓

Service

↓

Repository

↓

Database
```


---

## 示例


训练模块：


```text id="lj1h0n"
TrainingPage

↓

TrainingService

↓

TrainingRepository

↓

IndexedDB
```


---

# 4. 建立 Repository 数据访问层


## 目标

隔离数据库实现。


---

## 原问题


页面直接：

```typescript
db.training.add()
```


导致：

未来切换：

IndexedDB

↓

Supabase

需要大量修改。


---

## 新架构


```typescript
trainingRepository.create()
```


内部决定：

数据来自：

- IndexedDB
- Supabase
- API
