# Charisma Lab｜个人魅力成长实验室

这是一个中文、本地优先的长期学习与成长应用。当前正式发布版本为 **v0.1.1**：可以制定目标、学习表达课程、进行场景练习、记录现实训练、填写行为自评和写成长日志，数据先保存到当前浏览器的 IndexedDB。

仓库已有可选 Supabase 登录、双向同步、冲突处理与 SQL 迁移代码，并有本地自动化测试。未配置真实托管 Supabase 项目，也未完成该环境的双设备与生产验收；未配置时继续使用完整本地模式，Outbox 不会自动上传到一个不存在的云项目。

应用鼓励自主、平等、有边界的人际关系，不计算容貌、人格价值或所谓异性吸引力分数。

## 2. 技术与数据流

使用 React、TypeScript、Vite、Tailwind CSS、React Router、Lucide、Recharts、Zod、Dexie、dexie-react-hooks、vite-plugin-pwa / Workbox。测试使用 Vitest、React Testing Library、fake-indexeddb 和 Playwright。

页面通过 Service → Repository 读取和修改本地数据。重要修改在同一个 IndexedDB 事务中更新业务记录和 Outbox；事务提交成功后才反馈“已保存到本机”。静态课程随应用一起构建，个人记录保存在数据库中，两者分开管理。

```text
页面 → Service → Repository → IndexedDB：私人记录 + Outbox（同一事务）
                     ↓
             响应式查询更新页面

PWA Service Worker → 缓存 HTML / JS / CSS / 图标 / 随构建打包的课程
```

游客空间的 Outbox 不表示已登录或已上传。已配置并授权的账号可由同步引擎处理账号空间的待同步记录；业务页面仍经 Service / Repository 写入本机，不能把本地保存提示当作云端同步成功。

已经有 `package-lock.json` 时，重新安装或在另一台机器部署可使用 `npm ci`，按锁定版本安装。不要手动删除学习数据来解决依赖问题，浏览器数据库与 `node_modules` 是两回事。

## 8. 离线模式与安装 PWA

1. 运行生产版本并在有网络时打开页面。
2. 等待界面显示“应用资源已缓存，可以离线打开本应用。”。未成功访问或未完成缓存时，不能承诺首次断网可打开。
3. 创建一篇测试日志并记录一项训练，等待“已保存到本机”。
4. 在 Chrome 开发者工具的 Network 面板选择 Offline，刷新页面，再编辑日志和新增训练。
5. 关闭页面，在同一浏览器、同一地址重新打开。已经缓存的应用应继续显示本地记录。
6. 恢复网络。未配置云项目时数据继续留在本机；只有正确配置并登录的账号空间才会尝试云端同步。

Chrome 提供安装入口时，可点击地址栏安装图标或浏览器菜单的安装应用入口。手机上用浏览器的“安装应用”或“添加到主屏幕”，具体入口随浏览器不同。桌面本机 `localhost` / `127.0.0.1` 可以用于 PWA 调试，正式手机离线安装应使用 HTTPS。

Service Worker 只缓存应用资源。私人日志等业务内容在 IndexedDB，不缓存认证令牌或私人 API 响应。应用更新使用提示式更新：保存正在编辑的内容后再确认刷新。更新提示机制见 [Vite PWA 官方说明](https://vite-pwa-org.netlify.app/guide/auto-update)。

在“数据与同步设置”中申请持久化存储，并查看浏览器是否允许。申请被拒绝不影响当前学习，但应继续定期导出备份。

## 9. 创建 Supabase 项目（可选，真实云端验收未完成）

本地模式不需要创建项目。仓库已有 Supabase SDK 认证、同步引擎、RLS SQL 迁移和本地测试；这些证据不等于已经在真实托管 Supabase 上执行迁移或通过跨设备验收。

以后接入时，在 [Supabase 控制台](https://supabase.com/dashboard) 创建自己的项目，保管数据库密码；在项目连接或 API 设置中取得项目 URL 与公开 publishable key。浏览器只能使用公开发布密钥。`secret` / `service_role` 密钥能绕过重要访问保护，不能放进前端、仓库或 `VITE_` 变量。密钥类型见 [Supabase 官方文档](https://supabase.com/docs/guides/getting-started/api-keys)。

真实云功能必须使用你的项目公开配置，并在数据库迁移、授权和测试全部完成后启用。私人学习数据不会因创建项目而自动上传。

## 11. 数据库迁移

当前数据库是 Dexie 管理的本地 IndexedDB。第一次访问会创建数据库；新增本地结构应通过递增 Dexie schema 版本和迁移实现，不能让用户通过清空站点数据完成升级。

仓库已有 `supabase/migrations/202610130001_reliable_sync.sql`，包含云端同步所需表、权限与版本条件写入逻辑，并有本地 SQL 测试。真实托管项目尚未执行和验收该迁移；执行前请在独立测试项目审阅和验证，不要把设计文档中的示意 SQL 当成迁移。

配置真实云端时先确认迁移内容与项目环境，执行迁移后验证两账号隔离、版本条件写入和登录回调，再做双设备测试。不要在本地应用中使用管理员密钥。

## 12. RLS 与认证回调

仓库 SQL 为私人表定义 RLS、GRANT 与归属校验，本地测试覆盖关键隔离行为。真实项目部署后仍须复核 SELECT、INSERT、UPDATE、DELETE 和版本条件更新。RLS 是服务器访问控制，不等同于端到端加密。参考 [Supabase RLS 官方说明](https://supabase.com/docs/guides/database/postgres/row-level-security)。

当前认证代码使用邮箱 OTP / Magic Link。验证码邮件模板、站点 URL 和回调地址须在自己的真实项目中配置并验证。参考 [邮箱无密码登录文档](https://supabase.com/docs/guides/auth/auth-email-passwordless)。

使用 Magic Link 时，在 Authentication 的 URL Configuration 设置正式 Site URL，将实际使用的开发和正式回调地址加入允许列表；实际路径以当前认证实现和部署域名为准。参考 [Supabase 回调地址文档](https://supabase.com/docs/guides/auth/redirect-urls)。

## 13. 手机、电脑与同步验收

未配置真实云项目时，手机和电脑各自保存自己的数据，没有自动跨设备同步。此时可使用 JSON 备份文件手动迁移。

仅用于同一 Wi-Fi 的界面测试，可启动：

```powershell
npm run dev -- --host 0.0.0.0
```

手机访问电脑的局域网 IP，例如 `http://192.168.1.10:5173`。Windows 防火墙可能需要允许 Node.js 在专用网络中监听。不要把开发服务器当成公开部署；普通局域网 HTTP 也不满足手机 PWA 的安全来源条件。

真实托管环境的双设备验收仍需验证：同一账号在 A 创建 → B 同步读取 → B 修改 → A 获取修改；A 离线修改与 B 在线修改同一日志时，A 必须保留两份内容并显示冲突选择。账号 A 退出、账号 B 登录后，B 不得读取 A 的本地或云端记录。仓库已有本地模拟和 SQL 安全测试；由于尚未配置真实项目，不能将其称为真实双设备验收通过。

## 14. 导出、恢复与删除数据

在“数据与同步设置”使用完整 JSON 备份。备份包含版本、导出时间及所有私人业务记录和软删除标记，不包含静态课程资源、Outbox 或认证令牌。备份文件含个人笔记和日志明文，请存放在可信位置；应用的私密默认值不等于数据加密。

备份使用统一记录模型，课程进度、训练、测评、日志、目标、设置等由 `kind` 区分，而不是多份单独命名的顶层数组：

```json
{
  "schemaVersion": 1,
  "appVersion": "v0.1.1",
  "exportedAt": "2026-10-13T00:00:00.000Z",
  "records": []
}
```

示例的空数组仅说明文件格式，实际导出会包含当前空间的记录。`schemaVersion: 1` 是 JSON 结构版本，和应用标识 `appVersion` 无关；旧备份的 `appVersion: "2.0.0-p1"` 仍按同一 Schema 校验。导入拒绝未知类型、重复 ID、不支持的 Schema 版本和不完整的结构；导入记录归属当前空间，不把备份里的身份或云版本当作授权。

导入先校验文件结构和 schemaVersion，再显示记录预览；确认后选择：

- **合并**：新增不存在的 ID；相同 ID、相同内容跳过；相同 ID、不同内容保留原记录并另存导入副本。重复导入相同副本会跳过，不自动按设备时间裁决长篇内容。已有计划、主题、课程进度和笔记继续优先显示；课程笔记侧栏可选择导入副本。
- **替换**：整体替换恢复仅适用于游客空间；替换游客空间的业务数据需要再次确认，并先保留恢复用的安全备份。账号空间不允许整体替换，仍可使用合并恢复。

导入通过数据库事务执行，校验失败或事务失败时保留原有业务数据。重要操作前仍请另外下载一份 JSON，数据库内的安全快照不能抵御浏览器清除全部站点数据。

训练记录和测评结果可分别导出 CSV，适合 Excel 查看统计。普通 CSV 不包含私人日志。文本字段进行公式注入防护，以免以 `=`, `+`, `-`, `@` 等开头的文本被表格软件当作公式。CSV 不能代替完整 JSON 恢复。

删除日志使用软删除，界面隐藏记录并保留 Tombstone，供已配置的账号同步传播删除；当前不会自动清理 Tombstone。清空游客记录需要二次确认，只处理当前应用的游客空间，先保存安全快照；**清空后仍保留数据库内的安全快照，供误操作恢复，因此不是彻底擦除私人信息**。如需要彻底删除当前浏览器来源的数据，在另行备份并确认后使用 Chrome 的站点数据删除功能；该操作同时失去安全快照和离线缓存。没有实际配置云项目时，不存在可操作的云端账号数据。

需要清楚记住：

- 浏览器本地存储不是独立备份。清除站点数据、浏览器卸载、设备故障都可能导致记录丢失。
- 无痕窗口通常会在结束会话后清除数据，不适合长期记录。
- `http://localhost:5173`、`http://127.0.0.1:5173`、`:4173`、局域网地址、Sites 地址或正式域名是不同来源，不共享 IndexedDB。
- 更换地址、浏览器或设备前，先从原地址导出，再在新地址导入。
- 未配置并验收真实云项目时，“等待同步”不能提供跨设备或灾难恢复保障。

## 15. 部署到 HTTPS

执行 `npm run build` 后，将 `dist/` 目录的内容作为静态站点部署在 HTTPS 来源。根目录应包含 `index.html`、JS/CSS、图标、Manifest 和 Service Worker。当前默认配置面向域名根路径；如使用子目录部署，需同时调整 Vite base、Manifest start_url 与资源路径并重新测试。

HashRouter 的 `/#/journal` 等业务路由不会要求服务器把 `/journal` 重写到首页。首次访问应在线完成缓存；安装后的应用仍依赖该浏览器来源的数据。

本项目已通过 Sites 私有部署，工具返回 `succeeded`：[打开 Charisma Lab](https://charisma-lab-zzx.freshhare64.chatgpt.site)。网站保持仅本人可访问；发布状态已确认，线上设备的离线使用仍需各自完成首次缓存。其他 HTTPS 静态托管也可使用生产产物。Sites 的访问登录只控制网站访问，不会启用本应用的 Supabase 云同步；手机与电脑仍各自拥有本地数据，需要通过 JSON 备份迁移。

从本地地址迁移到 HTTPS 地址时，先导出备份，在新地址导入。不要预期正式站点会自动读取电脑 `127.0.0.1` 中的私人记录。

## 16. 检查、测试与常见问题

```powershell
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

第一次安装 Playwright 浏览器需要网络。端到端测试使用独立浏览器上下文和测试数据，不需要清空你常用浏览器的私人数据库。具体已执行结果见开发记录，不把命令列表当成通过证明。

| 问题 | 处理方法 |
| --- | --- |
| `node` 或 `npm` 找不到 | 安装 Node.js 后重新打开终端，检查 `node --version` |
| Node 版本不兼容 | 使用满足 `>=22.12` 的受支持版本后重新安装依赖 |
| PowerShell 限制 `npm.ps1` | 使用 `npm.cmd` |
| 端口被占用 | 关闭旧的开发终端，或按 Vite 输出的新地址访问；新端口拥有独立本地数据 |
| 页面刷新后没有原来的数据 | 核对协议、主机名、端口、浏览器和用户窗口是否一致；从原地址导出恢复 |
| 开发模式不能离线打开 | 使用 `npm run build` 和 `npm run preview`，先在线完成缓存 |
| 手机无法安装 PWA | 使用 HTTPS 正式站点；检查缓存、Manifest、浏览器安装条件 |
| 持久化存储申请未获批准 | 正常使用并定期下载备份，浏览器自行决定授权 |
| 日志没有显示“已保存到本机” | 等待保存完成；若出现错误，先保留文本，检查磁盘空间和浏览器 IndexedDB 权限 |
| 已填写 Supabase 配置仍无登录 | 检查公开密钥、项目迁移、认证回调及网络；本地代码测试不能替代真实项目联调 |
| 刚更新仍看到旧界面 | 保存正在编辑的数据后接受更新提示；必要时关闭旧页面重新打开，勿为更新而清除站点数据 |
| 备份导入被拒绝 | 检查是否为本应用导出的完整 JSON 与受支持 schemaVersion；不要手工修改成绕过校验的结构 |

## 17. 如何添加课程与继续迭代

课程放在 `src/content/`，不写在页面 JSX 中。先阅读 `src/content/types.ts` 和 M04 示例，新增时遵循：

1. 分配稳定、唯一的 ID，例如 `M04-L04`；已发布 ID 不随标题修改。
2. 写明课程目标、时间、核心概念、正反案例、误区、分支练习、现实任务、理解检测。
3. 将课程加入对应模块目录，题目和答案引用必须有效。
4. 训练和情景使用独立稳定 ID，提供具体反馈，不把复杂社交问题写成唯一正确套路。
5. 运行类型检查、内容校验测试和构建；检查课程页和离线构建是否可读取新内容。
6. 已保存的进度和笔记引用旧 ID，应继续能够恢复。删除内容前制定迁移或归档方式。

推荐开发顺序：先保证 P0 数据闭环 → P1 经测试的云授权与同步 → P2 扩充真实内容 → P3 解释清晰的分析 → P4 体验优化。不要为了新主题或动画绕过事务、数据校验、备份或身份隔离。

完整后续任务及同步原理见 [开发记录](DEVELOPMENT.md) 和 [P1 同步设计](docs/P1-SYNC-DESIGN.md)。
