## B. 真实托管项目与权限

- [ ] 在真实托管 Supabase 测试项目配置公开密钥、站点 URL 和允许的认证回调；记录配置来源，不记录密钥本身。
- [ ] 执行并核对 `supabase/migrations/202610130001_reliable_sync.sql`；验证表、索引、GRANT、RLS、RPC 与实际项目角色权限，保存执行结果和迁移版本。
- [ ] 使用项目实际启用的邮件流程完成首次邮箱 OTP 登录/创建账号、退出、重新登录和会话恢复；验证错误验证码、过期会话与离线新登录的反馈。若项目启用 Magic Link，还需单独验证真实回调。
- [ ] 以账号 A 创建私人记录，账号 B 通过浏览器界面及直接数据库 API 分别尝试 SELECT、INSERT、UPDATE、DELETE 或相关 RPC；确认不能读取或修改 A 的记录，也不能通过更换 `owner_id` 越权。再验证 B 自己的正常读写。
- [ ] 退出 A 后登录 B，验证当前设备不展示 A 的本地私人内容；恢复 A 时仍能读取 A 的记录。游客记录保持独立。

## C. 两设备与本地优先闭环

- [ ] 使用两个真实独立浏览器资料空间或两台设备登录同一账号：A 保存课程进度和笔记、新增训练记录和成长日志、提交测评/自评；B 同步后逐项读取并核对原记录。B 再编辑进度/笔记、更新训练记录和日志，A 拉取并核对；训练记录和日志的删除也分别验证跨设备生效。B 另行提交测评/自评后，A 同步并逐条核对多次提交生成的测评结果和自评记录，包括数量、ID、提交时间及答案或分数；不要求修改、删除既有结果或回滚到旧版本。其余六种私人记录类型逐项核对账号隔离与往返结果。
- [ ] 不登录时完成游客学习、训练与日志记录；登录后明确选择“合并”“保留不合并”或“取消”，分别核对记录数量、原游客数据保留、当前账号归属与重复迁移的幂等性。迁移前下载独立 JSON 备份。
- [ ] A 先在线打开并缓存应用，再离线保存或编辑学习进度/笔记、新增/修改/软删除训练记录与日志、提交测评/自评；刷新后确认本地保存及待同步数量准确。恢复网络后验证自动同步、手动同步及 B 的数据恢复，区分“已保存到本机”和“已同步到云端”。
- [ ] 注入网络中断、服务端错误、请求超时或客户端未收到已提交响应；核对 Outbox 持久保留、重试退避、会话失效提示、部分成功后继续处理，以及相同 `mutationId` 重发不重复、不误覆盖。
- [ ] A 离线、B 在线修改同一篇日志后让 A 联网；确认服务端版本比较阻止静默覆盖，界面保存并展示两份内容，分别验证保留本地、保留云端、手动合并和暂缓处理。软删除冲突及长期离线旧设备不得复活旧 ID。
- [ ] 课程笔记并发修改：设备 A 与 B 登录同一测试账号，先同步并核对同一条笔记的初始内容及版本一致；在受控条件下分别修改笔记（例如 A 离线编辑、B 在线编辑），再触发同步。核对版本冲突检测、双方内容保留与可恢复性，确认没有未检测的静默覆盖或数据丢失，并记录实际处理结果。现有同步设计仅明确通用的冲突检测与双方保留，未单独定义课程笔记适用的解决策略及副本处理规则；正式验收前须明确该策略和用户可执行的解决路径，再按所定策略验证，未明确或未实测前保持待验收。
- [ ] 删除测试记录后在 B 同步并确认隐藏；检查 Tombstone 的保留与权限。核对导出备份、恢复及安全快照不改变账号身份或授予上传授权。
